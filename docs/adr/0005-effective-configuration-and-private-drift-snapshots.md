# ADR-0005：有效配置与隐私保护的漂移快照

- Status: Superseded by ADR-0006 (2026-08-05)
- Date: 2026-07-23

## 背景

AgentGuard 需要从“发现配置文件中有什么”扩展到“解释 Agent 当前真正使用什么”，并把当前状态与用户确认过的
可信状态比较。有效配置在本机运行时需要路径、规范化端点和集成身份来解释覆盖关系，但这些信息如果原样写入
长期快照，会扩大项目身份、内部网络和本机目录泄露风险。普通 SHA-256 也不足以保护常见路径和端点，因为其
输入空间可以被离线枚举。

有效配置还会同时供 CLI、JSON、HTML 和 Desktop 使用。若每个入口自行解析优先级、保存不同数据或把首次扫描
自动设为可信，用户会得到不一致结论，并可能把已有风险固化为基线。

## 决策

1. Adapter 负责理解各 Agent 的配置来源与优先级，core 使用统一的 `EffectiveAgentState` 表示计算结果。
   CLI、报告和 Desktop 只消费该 typed core 结果，不自行重新计算配置优先级。
2. 运行时有效状态与持久化漂移快照使用两个独立模型。运行时状态可以包含完成本机解释所需的路径、规范化
   端点和集成身份，但不得包含完整凭证；它不能直接序列化为快照。
3. `DriftSnapshot` 只保存比较所需的 allowlist 字段：Agent ID 与版本、来源/认证/权限枚举、稳定冲突代码、
   已登记规则 ID，以及路径、端点、模型和集成身份的 keyed HMAC。
4. 身份摘要使用 HMAC-SHA-256，并按数据类别和 Agent 做上下文隔离。首次创建 32 字节随机本机密钥，
   默认保存为 `~/.agentguard/state-key`；目录权限为 0700，文件权限为 0600。
5. 本机密钥缺失、损坏或权限过宽时拒绝读取和写入已有快照，不静默重建。不同本机密钥生成的身份不能用于
   跨机器关联。
6. 快照按当前项目的不可逆 `scopeId` 隔离，使用严格版本与字段校验、0600 文件和同目录原子写入。损坏、
   未知版本、未知字段或权限错误必须在覆盖旧文件前失败。
7. 可信基线只能由用户显式确认后创建、替换或删除。首次扫描没有基线时只解释当前状态，不能自动信任。
8. `DriftEvent` 使用统一枚举和稳定身份语义；具体比较、排序、复扫和用户界面在后续里程碑实现。

## 不可破坏约束

- 快照不得保存 API Key、Token、OAuth 凭据、私钥、配置值、原始路径、原始端点、模型名、集成身份、
  evidence、taskId 或动态错误文本。
- 配置字段名、冲突代码和规则 ID 必须通过受限 schema；未知字段不能被宽松透传到持久化文件。
- 相同 key、上下文和值必须产生稳定身份；不同 key 或不同上下文必须产生不同身份。
- 新增快照字段时必须同时更新类型、严格读取校验、隐私测试和本文档；不能只修改写入侧。
- 删除密钥不能成为清空或覆盖旧快照的隐式手段。恢复能力必须保持身份密钥与快照的一致性。
- 第一版只做用户主动扫描和比较，不增加后台守护进程、文件监听或自动网络上传。

## 影响

- Adapter 需要输出比现有 finding 更完整的来源、覆盖、认证、权限和集成状态，但敏感值仍只能留在解析过程
  的内存中。
- 快照中的 HMAC 适合判断“是否相同”，不支持还原或跨机器合并；跨机器 Dashboard 需要单独的隐私与身份设计。
- 本机密钥和快照成为一个一致性单元。用户丢失密钥后需要明确删除旧基线再创建新基线，而不是自动继续。
- E0 只建立 schema 与存储边界，不代表当前 CLI/Desktop 已经能够展示有效配置或 Drift。

## 未采用方案

- 直接保存 `EffectiveAgentState`：会把路径、端点和集成身份写入长期状态。
- 对路径和端点使用普通 SHA-256：常见值容易被字典枚举，且可跨机器关联。
- 使用随机 salt 且每次重建：相同状态无法稳定比较。
- 首次扫描自动创建基线：可能把已有风险或被篡改状态标记为可信。
- 立即增加后台监听：扩大权限、生命周期和误报面，不符合当前手动比较边界。
