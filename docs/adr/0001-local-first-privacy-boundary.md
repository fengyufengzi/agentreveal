# ADR-0001：本地优先与最小持久化隐私边界

- Status: Accepted
- Date: 2026-07-17

## 背景

AgentGuard 读取 AI Coding Agent 的配置，其中可能包含凭证、内部端点、本机路径、权限和 MCP 信息。
这些数据对风险解释有价值，但上传、日志化或长期保存会产生新的泄漏面。产品当前不需要云端服务即可完成
发现、处置、验证和报告。

## 决策

1. 扫描、规则判断、任务聚合和报告生成默认全部在本机完成，不自动上传扫描结果或诊断。
2. 运行时 finding 和用户主动导出的报告可以显示处置所需的规范化端点与配置路径，但不得包含完整凭证。
3. parser 输出和 evidence 只保留存在性、键名、数量、规范化标识或不可逆指纹；不得返回原始密钥值。
4. 风险接受、任务快照和诊断属于长期持久化数据，必须进一步最小化：
   - acceptance/task snapshot 不保存项目路径、动态标题、端点或 evidence；
   - diagnostics 不保存项目路径、端点、taskId、配置内容或原始错误文本。
   - 项目规则忽略只保存 Agent、ruleId、原因、创建/到期时间和追加式变更审计，不保存 finding evidence、
     taskId、路径或端点；原因可能进入版本控制，界面必须提醒用户不要填写秘密。
5. 本地状态目录使用 0700、文件使用 0600，并采用原子写入。
6. 报告和诊断只能由用户主动选择位置导出；发送给第三方前仍由用户检查内容。

## 不可破坏约束

- 不得为了调试方便增加原始配置、异常上下文或请求内容日志。
- 不得把真实用户配置复制到 fixture、Issue、PR、文档或仓库历史。
- 新增任何网络上传、遥测、云同步或远程诊断能力前，必须提出新 ADR，说明同意机制、数据字段、保留期限、
  删除方式和关闭路径。

## 影响

- 支持问题可能缺少完整现场信息，需要通过固定错误分类和合成复现补足。
- 端点仍可出现在本地报告中，因为用户需要据此确认归属；“本地展示”不等于“可持久化到所有状态文件”。
- 隐私回归必须检查完整序列化输出，不能只检查某个字段。

## 未采用方案

- 默认上传匿名报告：路径、端点和错误组合仍可能重新识别用户环境。
- 完整本地 debug log：同一用户账户下的其它进程或误发送仍可能泄漏配置。
