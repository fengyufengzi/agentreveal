# ADR-0003：配置写入必须是可预览、可恢复事务

- Status: Accepted
- Date: 2026-07-17

## 背景

安全工具自动修改 Agent 配置可能造成配置丢失、权限变化、并发覆盖或凭证进入备份。相比漏修一个提示，
损坏用户正在使用的配置影响更大。因此自动化率不能作为主要成功指标。

## 决策

1. discovery、scan、map、report 和 baseline dry-run 默认只读。
2. 自动写入只覆盖能够可靠解析、保留无关字段并安全序列化的有限格式和规则。
3. apply 必须使用用户已查看的计划，并在写入前重新校验源文件哈希和计划 fingerprint。
4. 写入前强制创建带 manifest、原路径、原权限和内容摘要的完整备份。
5. 使用同目录临时文件、fsync、权限保持和原子 rename；多文件部分失败时自动恢复已写文件。
6. apply 完成后立即重新扫描，不能把“写入成功”当作“风险已解决”。
7. restore 必须验证备份 ID、路径边界、manifest、内容完整性以及 apply 后的当前文件状态；发现外部修改时拒绝覆盖。
8. 备份目录和文件仅当前用户可读，并具备 Git 忽略保护。

## 不可破坏约束

- 不允许没有 dry-run、显式确认和备份的一键修改。
- 不允许 renderer、报告 HTML 或复制按钮绕过主进程/CLI 的事务边界直接写文件。
- 不允许为提高自动化率修改 CC Switch SQLite 或无法可靠保留注释与结构的配置。
- 新写入对象必须覆盖无变化、并发修改、权限保持、备份篡改、部分失败和恢复测试。

## 影响

- 一部分风险只能提供引导式修复，直到目标 Agent 提供安全 helper/API 或项目具备可靠 serializer。
- 完整原配置备份本身包含敏感数据，因此不得进入报告、诊断或 Git。
- 写入实现需要更多代码和测试，但把不可恢复配置损坏从正常风险变为阻断式失败。

## 未采用方案

- 直接编辑字符串或正则替换：无法可靠处理格式、注释、重复键和并发写入。
- 只备份被修改字段：无法证明可恢复原文件，也容易遗漏格式和未知字段。
