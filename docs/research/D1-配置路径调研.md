# D1 · AI Coding Agent 配置路径调研表

> Spike 交付物 D1 | 版本 v0.1 | 日期 2026-07-09
> 目的：为各 adapter 提供"去哪里找配置、配置长什么样、密钥在哪、要不要读"的地基。
> 关系：对应技术 Spike 清单模块 B（Agent Discovery）与 D1 交付物。

## 0. 调研方法与可信度说明

- **一手验证（macOS）**：本机实际安装了 Claude Code、Codex、CC Switch、Gemini CLI、**OpenCode（v1.17.16，为本次调研新装）**，直接探测了目录结构与配置**结构**（只读 schema / 顶层键名，未读取任何密钥值），OpenCode 另用样例 `opencode.json` 跑 `opencode models` 验证了解析行为。
- **约定推断（Windows / Linux）**：本机为 macOS，其他平台路径依据各工具公开约定给出，标注为「待实测」。
- **可信度标记**：🟢 本机实测 / 🟡 约定推断，需实测 / ⚪ 未验证。

> ⚠️ 头号结论先说：**CC Switch 当前版本用 SQLite 存配置（不是 JSON 文件），且内置本地代理**。这与立项文档"解析 CC Switch 配置文件"的假设不符，必须修订 adapter 设计（见 §6）。

## 3. CC Switch  ⭐（核心差异点，结论已变）

| 项 | 内容 | 可信度 |
|---|---|---|
| 配置目录 | `~/.cc-switch/` | 🟢 |
| **主配置（新版）** | **`~/.cc-switch/cc-switch.db`（SQLite 3，`user_version=10`）** | 🟢 |
| 附属文件 | `settings.json`（应用设置）、`logs/cc-switch.log`、`backups/db_backup_YYYYMMDD_*.db`（CC Switch 自带 DB 备份） | 🟢 |
| 旧版配置 | 历史版本使用 `~/.cc-switch/config.json` —— **adapter 需同时兼容 JSON 旧格式与 SQLite 新格式** | 🟡 |
| Windows / Linux | 预期同为 `~/.cc-switch/`（Tauri 应用，配置在 home） | ⚪ |
| **密钥位置** | 在 `providers.settings_config`（TEXT，内嵌 JSON，含各 app 的 base_url + apiKey）——**要判断"同 key 多 Agent 复用"必须读该值**，与"默认不读内容"存在张力，需在信任机制里单列规则（见 §6.3） | 🟢 |

**关键表结构（实测 schema）**：

- `providers(id, app_type, name, settings_config, category, provider_type, is_current, in_failover_queue, cost_multiplier, limit_daily_usd, limit_monthly_usd, ...)`
  - `app_type` 本机实测取值：`claude` / `codex` / `gemini` / `openclaw`（**注意：不一定含 opencode，取值随版本/用户而变，不能硬编码**）
  - `settings_config` 是 JSON blob，真正的 base_url / apiKey 在里面，按 app_type 结构不同
  - `is_current` 标记当前激活的 provider
- `provider_endpoints(provider_id, app_type, url)` —— 每个 provider 的候选 endpoint 列表
- `mcp_servers(id, name, server_config, enabled_claude, enabled_codex, enabled_gemini, enabled_opencode, enabled_hermes)` —— **CC Switch 统一管理 MCP 并按 Agent 分发**
- **`proxy_config`** ⚠️ —— CC Switch **内置本地反向代理**：`app_type IN (claude,codex,gemini)`、`listen_address`（默认 `127.0.0.1`）、`listen_port`（默认 `15721`）、`auto_failover_enabled`、熔断参数等
- `proxy_request_logs` / `proxy_live_backup` / `provider_health` / `stream_check_logs` —— 代理运行时数据
- 其他：`prompts`、`skills`、`skill_repos`、`model_pricing`、`usage_daily_rollups`、`settings`

**这是 D1 最重要的发现，含三层结论**：

1. **格式变了**：CC Switch adapter 从"读 JSON 文件"改为"打开 SQLite，读 `providers.settings_config` 的 JSON blob，按 `app_type` 分别解析"，并**向后兼容旧版 `config.json`**。
2. **多了一个代理层**：当 `proxy_config.proxy_enabled=1` 时，Claude/Codex/Gemini 的 base_url 会被指到 `127.0.0.1:15721`。AgentGuard 若只看 Agent 自身配置会误判为"本地安全地址"，**真实上游必须回到 CC Switch DB 里解析**。这既是一条新风险规则，也是配置地图必须画出的一跳。
3. **CC Switch 是 MCP 与 Provider 的分发中枢**：它统一管理 MCP 并写入各 Agent。治理 CC Switch 等于治理上游源头，进一步印证其"核心差异点"地位——但也再次确认它是**单点故障**（schema 版本号已到 v10，迭代快）。

## 5. OpenCode  🟢（已实测，v1.17.16，`npm i -g opencode-ai`）

| 项 | 内容 | 可信度 |
|---|---|---|
| 全局配置 | `~/.config/opencode/opencode.json`（遵循 XDG，受 `XDG_CONFIG_HOME` 影响；默认**不自动生成**，用户建了才有） | 🟢 |
| 项目配置 | `<project>/opencode.json`（实测在项目目录放该文件即被读取、生效） | 🟢 |
| 全局 TUI 配置 | `~/.config/opencode/tui.json` | 🟢 |
| 数据目录 | `~/.local/share/opencode/`（含 `opencode.db` SQLite 会话库、`auth.json`、`log/`、`storage/`、`snapshot/`）——**属运行数据，非用户配置，adapter 不解析** | 🟢 |
| 缓存目录 | `~/.cache/opencode/`（`models.json`、内置 `rg` 等） | 🟢 |
| **密钥位置** | `~/.local/share/opencode/auth.json`（独立于主配置；`opencode auth list` 实测确认路径）。此外 config 里 apiKey 常写成 `{env:XXX}` 引用环境变量 → **密钥通常不落在 config 里** | 🟢 |
| 覆盖变量 | `XDG_CONFIG_HOME`（影响全局 config 目录）；`OPENCODE_CONFIG`（约定，🟡 未逐一实测） | 🟡 |
| Schema | `https://opencode.ai/config.json`（config）/ `https://opencode.ai/tui.json`（TUI） | 🟢 |
| Windows | `%USERPROFILE%\.config\opencode\`（XDG 风格） | ⚪ |

**配置结构（实测样例，已通过 `opencode models` 验证可被正确解析、无 schema 报错）**：

```json
{
  "$schema": "https://opencode.ai/config.json",
  "model": "anthropic/claude-sonnet-4-5",
  "provider": {
    "myrelay": {                         // 自定义 provider，key 即 provider 名
      "npm": "@ai-sdk/openai-compatible",
      "options": {
        "baseURL": "https://api.unknown-relay.example.com/v1",  // ← 中转/未知 endpoint 从这里判
        "apiKey": "{env:RELAY_KEY}"       // ← 引用环境变量，密钥不在文件里
      },
      "models": { "gpt-x": {} }
    }
  },
  "permission": {
    "*": "ask",
    "edit": "allow",
    "bash": { "*": "allow", "rm -rf *": "deny" },  // ← 通配 allow 即高风险信号
    "webfetch": "allow"
  },
  "autoupdate": true,
  "mcp": {
    "fs":          { "type": "local",  "command": ["npx","-y","@modelcontextprotocol/server-filesystem","/"], "enabled": true },  // ← command 挂根目录 = 高危
    "remote-tool": { "type": "remote", "url": "https://mcp.unknown.example.com/sse", "enabled": true }                             // ← 未知 remote MCP
  }
}
```

**解析要点（对应 PRD §6.2 的 OpenCode 规则）**：
- **Provider / base_url**：遍历 `provider.<name>.options.baseURL`；无 baseURL 即用官方；有则查 Provider 信任库。`npm: "@ai-sdk/openai-compatible"` 是"OpenAI 兼容未知端点"的强信号。
- **auto mode / 权限**：OpenCode **没有单一 "auto mode" 开关**，风险体现在 `permission`：`edit/bash/webfetch` 取值 `allow|ask|deny`；`bash` 支持按命令模式覆盖。`"*": "allow"` 或 `bash."*":"allow"` = `OPENCODE_PERMISSION_WILDCARD`。另有 `tools: {write/bash: true}`、`snapshot: false`（关闭回滚能力，风险项）、`autoupdate` 值。
- **MCP**：`mcp.<name>.type` 区分 `local`(用 `command`+`environment`) 与 `remote`(用 `url`)。`remote`+未知域名 = `MCP_REMOTE_UNKNOWN`；`local` filesystem server 参数含 `/` 或 `$HOME` = `MCP_FILESYSTEM_HOME`(critical)；`environment` 内联密钥 = `MCP_ENV_SECRET`。
- **密钥处理**：`{env:...}` / `{file:...}` 是引用而非明文 → Discovery 判断"是否已配置"探测 `auth.json` 存在即可，无需读值，天然符合"默认不读内容"。
- **配置合并**：全局 `~/.config/opencode/opencode.json` + 项目 `opencode.json` 会合并，adapter 需两处都读并标注来源。

## 6. 对规划/设计的影响（务必回写文档）

### 6.1 CC Switch adapter 重新定义
- 依赖 SQLite 读取（Node 侧用 `better-sqlite3`/`node:sqlite`），非纯文本解析。
- 需处理 schema 版本：读 `PRAGMA user_version`，对已知版本（当前 v10）解析，未知版本降级为"仅提示、不深解析"，避免版本漂移导致崩溃。
- 兼容旧版 `config.json`。

### 6.2 新增"代理链路"风险与地图能力
- 新规则（建议）：`CCSWITCH_PROXY_ENABLED` —— Agent base_url 指向 CC Switch 本地代理，真实上游在 DB。等级 info/medium（本身不危险，但会掩盖真实上游，需在地图展开）。
- 配置地图需支持"Agent → CC Switch 代理 → 真实 Provider"的两跳展示。

### 6.3 密钥读取策略需要一条明确例外
- 原则是"默认不读内容"，但"同 key 多 Agent 复用"检测（`CCSWITCH_SHARED_KEY` / `shared-api-key`）**必然要读到 key 才能比对**。
- 建议：只在内存中对 key 做哈希（如 SHA-256 前若干位）用于比对，**绝不落盘、绝不进报告**，报告只展示"检测到 N 个 Agent 复用同一密钥"。这条要写进信任机制章节。

### 6.4 `app_type` 不可硬编码
- CC Switch 的 `app_type` 取值随版本/用户变（本机是 claude/codex/gemini/openclaw）。adapter 应动态枚举 DB 里出现的 app_type，而非写死列表。

### 6.5 密钥与配置分离是普遍模式
- Codex(`auth.json`)、Gemini(`.env`)、OpenCode(`auth.json`) 都把密钥独立存放 → **Discovery 阶段判断"是否已配置"只需探测密钥文件是否存在，无需读值**，天然符合"默认只读/不读内容"。

### 6.6 跨平台缺口
- 5 个 Agent 的一手数据均来自 macOS（OpenCode 亦已在 macOS 实测）。Windows/Linux 路径仍为约定推断。**MVP 若承诺跨平台，需在 Windows/Linux 各补一次实测**；若 MVP 只保 macOS，需在 README 明示平台范围。
- OpenCode/Claude/Gemini 走 XDG，`XDG_CONFIG_HOME` 必须优先于 `~/.config` 读取（本机该变量为空，回落默认路径）。

## 7. Discovery 探测清单（供 adapter 直接实现）

优先级顺序：先读覆盖变量，再读默认路径。

```
Claude Code : $CLAUDE_CONFIG_DIR/  →  ~/.claude/ + ~/.claude.json  (+ 项目 .claude/, .mcp.json)
Codex       : $CODEX_HOME/         →  ~/.codex/config.toml (+ auth.json)
CC Switch   : ~/.cc-switch/cc-switch.db (新) | ~/.cc-switch/config.json (旧)
Gemini CLI  : ~/.gemini/settings.json (+ .env)
OpenCode    : $OPENCODE_CONFIG → $XDG_CONFIG_HOME/opencode/ → ~/.config/opencode/  (+ ~/.local/share/opencode/auth.json)  [待实测]
```

未发现某 Agent 时输出 `not found`，不报错（符合 Spike 模块 B 验收）。
