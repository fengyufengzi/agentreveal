## A. 《AgentGuard MVP PRD v0.2》

### A1. 🔴 §6.3 CC Switch Adapter —— 配置载体从"文件"改为"SQLite + 代理层"
**原文假设**：解析 CC Switch 配置文件（隐含 JSON 文本）。
**实测**：当前版本用 `~/.cc-switch/cc-switch.db`（SQLite，`user_version=10`），旧版才是 `config.json`；且内置本地反向代理。

**修订为**：
- 数据源：优先 `~/.cc-switch/cc-switch.db`（SQLite），向后兼容旧版 `~/.cc-switch/config.json`。
- 解析路径：读 `providers` 表 → 按 `app_type` 取 `settings_config`(JSON blob) 里的 base_url/apiKey；`is_current` 为当前激活；`provider_endpoints` 为候选 endpoint；`mcp_servers` 为 CC Switch 统一分发的 MCP。
- 版本策略：读 `PRAGMA user_version`，已知版本深解析，未知版本降级为"仅提示不深解析"。
- `app_type` **不可硬编码**（本机实测为 claude/codex/gemini/openclaw，随版本/用户变），需动态枚举。

### A2. 🟢 §6.3 CC Switch —— 新增规则：内置代理链路
新增规则（并入 CC Switch 规则表）：

| 规则 ID | 风险 | 等级 |
|---|---|---|
| `CCSWITCH_PROXY_ENABLED` | Agent base_url 指向 CC Switch 本地代理（默认 `127.0.0.1:15721`），真实上游被隐藏在 DB | info / medium |
| `CCSWITCH_PROXY_FAILOVER_UNKNOWN` | 代理 auto_failover 队列中含未知/未信任 Provider | high |

**判定依据**：`proxy_config.proxy_enabled=1` 且某 Agent base_url = `listen_address:listen_port`。
**报告要求**：配置地图必须展开"Agent → CC Switch 代理 → 真实 Provider"两跳，否则会把 `127.0.0.1` 误判为"本地安全地址"。

### A3. 🔴 §6.2 OpenCode Adapter —— `OPENCODE_AUTO_ENABLED` 规则重定义
**原文**：`OPENCODE_AUTO_ENABLED`（auto mode 开启，medium）。
**实测**：OpenCode **没有单一 auto mode 开关**，风险体现在 `permission` 段（`edit`/`bash`/`webfetch` 取 `allow|ask|deny`，`bash` 可按命令模式覆盖）。

**修订为**（替换/拆分该规则）：

| 规则 ID | 风险 | 等级 |
|---|---|---|
| `OPENCODE_PERMISSION_WILDCARD` | `"*":"allow"` 或 `bash."*":"allow"`（全放行） | high |
| `OPENCODE_BASH_UNRESTRICTED` | `bash` 无 deny 且默认 allow | high |
| `OPENCODE_SNAPSHOT_DISABLED` | `snapshot:false`（关闭回滚能力） | medium |
| `OPENCODE_AUTOUPDATE_ON` | `autoupdate:true`（供参考，低危） | low / info |

> 保留 `OPENCODE_PROVIDER_UNKNOWN` / `OPENCODE_MCP_REMOTE_UNKNOWN` / `OPENCODE_MCP_FILESYSTEM_HOME` / `OPENCODE_SECRET_IN_CONFIG` 不变。

### A4. 🟡 §6.2 OpenCode —— Provider 判定信号增强
`provider.<name>.npm: "@ai-sdk/openai-compatible"` + `options.baseURL` 指向未知域名，是"OpenAI 兼容未知中转"的强信号，比只看 base_url 更准。写入 Provider 判定逻辑。

### A5. 🟢 §6.1 / §6.6 —— 密钥"默认不读"落到实处 + 一条例外
- **落实**：Codex(`auth.json`)、Gemini(`.env`)、OpenCode(`auth.json`) 均把密钥独立存放，OpenCode/Claude 还支持 `{env:}` 引用 → **Discovery 判断"是否已配置"只需探测密钥文件是否存在，无需读值**。
- **例外**：`CCSWITCH_SHARED_KEY`（同 key 多 Agent 复用）检测必须读到 key。修订 §6.6/信任机制：**仅在内存对 key 做哈希（如 SHA-256 前若干位）比对，绝不落盘、绝不进报告**，报告只呈现"N 个 Agent 复用同一密钥"。

### A6. 🟡 §6.9 报告 / §5.2 配置地图 —— 增加"代理跳"列
配置地图与 HTML 报告需体现 base_url 是否经 CC Switch 代理，以及真实上游。（与 A2 联动）

### A7. 🟡 §15 技术合伙人待确认问题 —— 第 1 问已有答案
Q1"CC Switch 配置文件能否稳定解析？"→ **可解析，但为 SQLite（schema v10）非文本文件，需 SQLite 依赖 + 版本兼容策略**。建议把该问题标注为"已验证，见 D1"。

## B. 《AgentGuard 技术 Spike 任务清单 v0.1》

### B1. 🔴 模块 D（CC Switch Adapter）
- 「定位 CC Switch 配置文件」→「打开 `~/.cc-switch/cc-switch.db`(SQLite)，兼容旧版 `config.json`」。
- 新增验收：能读 `providers`/`provider_endpoints`/`mcp_servers`/`proxy_config`；能识别代理开启并还原真实上游。
- 技术依赖登记：Node 侧 SQLite 读取（`better-sqlite3` 或 `node:sqlite`）。

### B2. 🔴 模块 C（OpenCode Adapter）
- 「解析 auto mode」→「解析 `permission`(edit/bash/webfetch = allow/ask/deny)、`tools`、`snapshot`、`autoupdate`」。
- 补充路径：全局 `~/.config/opencode/opencode.json` + 项目 `opencode.json` 合并；密钥在 `~/.local/share/opencode/auth.json`。
- 已完成实测（v1.17.16），本模块可信度上调。

### B3. 🟡 模块 B（Agent Discovery）—— 探测清单落地
用 D1 §7 的探测清单替换泛化描述，明确覆盖变量优先级：`CLAUDE_CONFIG_DIR` > `~/.claude`；`CODEX_HOME` > `~/.codex`；`XDG_CONFIG_HOME` > `~/.config/opencode`。

### B4. 🟡 §1.2 Spike 边界 / 第 5 天备份回滚
CC Switch 自带 `~/.cc-switch/backups/db_backup_*.db`，backup/restore Spike 可参考其现成机制，降低 H 模块风险。

### B5. 🔴 Go/No-Go 判据修正（沿用上一轮规划评审结论）
「至少 3 个真实用户愿意试用 Demo」时机不当（Spike 末尾无可发 Demo），移至 MVP 第 4 周出口；Spike 出口只保留 6 条技术可行性判据。

## C. 影响汇总（一句话版）

1. CC Switch 是 **SQLite + 内置代理**，不是文件 → adapter 重写 + 新增代理链路规则 + 地图两跳。
2. OpenCode **无 auto mode**，风险在 `permission` → 规则重定义。
3. 密钥普遍独立存放 → "默认不读"可落实；唯一例外（复用检测）用内存哈希。
4. 覆盖变量（`CLAUDE_CONFIG_DIR`/`CODEX_HOME`/`XDG_CONFIG_HOME`）必须优先读。
5. Windows/Linux 仍待实测。
