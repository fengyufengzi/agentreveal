## 历史背景

在 0.0.2 阶段，项目曾采用私有仓库内部验证、暂缓公开发布的策略，主要原因包括：

- CLI 输出和配置结构仍在快速演进；
- 希望先完成本地扫描、报告和回滚闭环；
- 需要先验证隐私保护、脱敏输出和跨 Agent 兼容性；
- 尚未建立稳定的社区维护与公开发布流程。

该策略现已被新的“CLI 开源发布优先、桌面产品随后验证”的产品方向替代。

## 当前有效原则

- 代码、文档、示例和发布元数据只使用个人 Gmail 地址或 GitHub noreply 地址；
- 仓库不得包含公司名称、公司邮箱、公司域名、内部地址、客户信息或内部截图；
- 所有公开示例统一使用 `example.com`、`api.example.com`、`internal.example.com` 等保留示例域名；
- 所有密钥、Token、证书和私钥必须使用不可用占位符；
- 发布前必须执行 `npm run sanitize`；仓库公开前还必须执行 `npm run sanitize:history` 并处理全部命中；
- 当前文件不得作为开发排期或发布阻断条件的依据。

## 历史完成项

0.0.2 阶段已经完成的主要基础能力包括：

- CLI 构建、测试和本地分发；
- 多 Agent 发现与风险扫描；
- Provider、MCP、权限和敏感文件风险识别；
- HTML / JSON 报告；
- baseline、backup、apply 和 restore 的有限闭环；
- Electron 桌面预览壳；
- CI 基础验证。
