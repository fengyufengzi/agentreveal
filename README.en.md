## AgentGuard in 30 seconds

AgentGuard is a local security tool for the CLI and macOS Desktop. By default, it does not modify agent configuration.
It discovers and scans configuration for Claude Code, OpenCode, Codex, CC Switch, Gemini CLI, and OpenClaw, then identifies
unknown relay APIs, plaintext credentials, dangerous permissions, suspicious MCP servers, and hidden proxy chains.
Evidence is redacted throughout the process: complete secret values are never printed.

- **Discover** — `doctor` finds agents and their configuration paths.
- **Assess** — `scan` analyzes provider, MCP, credential, and permission risks.
- **Map** — `map` expands Agent → local proxy → real upstream chains.
- **Correlate** — shared proxies and unknown endpoints used by multiple agents are surfaced as concentration risks.
- **Act** — `report` groups work into act now, verify, clean up, and observe.

| Essential question | AgentGuard's answer |
|---|---|
| **Who does it connect to?** | AgentGuard itself does not connect to model providers. It reconstructs the providers, proxy upstreams, and MCP chains already configured on the machine. |
| **What does it read?** | Security-relevant configuration for six agent families. In the project directory, it checks sensitive file names only and does not read project file contents. Credentials are recognized in memory and complete values are excluded from output. |
| **What does it execute?** | `agentguard`, `doctor`, `scan`, `map`, and `report` are read-only with respect to agent configuration. Only explicit Advanced operations such as `apply` and `restore` modify supported configuration. |

See the [redacted sample output](examples/scan-output.txt), generated by running the real CLI against synthetic configuration.

## Quick start

> `agent-guard` package.

**Requirements:** Node.js 22 or later. `scan` and `map` use `node:sqlite` to read CC Switch configuration; development

### macOS Desktop Public Preview

The Electron desktop preview reuses AgentGuard core and stable task IDs rather than parsing terminal output. On first launch
it explains local execution, read-only defaults, and the no-upload policy. The initial flow has one primary action: select a
project and start scanning. Results lead with the overall conclusion, three priority tasks, and the actual provider/proxy/
upstream chain. HTML and JSON reports can be saved only to a location selected by the user. The signed and notarized
[Apple Silicon DMG is available from the matching GitHub Pre-release](https://github.com/fengyufengzi/AgentGuard/releases/tag/v0.0.6-pilot.4).

Task cards can accept risk, revoke acceptance, and verify status. Provider trust is separate: trusting an endpoint only
removes the unknown-source classification and never hides HTTP, plaintext credential, or dangerous permission findings.
Eligible non-fix P2/P3 rules may be ignored for the current project, agent, and rule ID, with a reason, expiry, revocation
audit, and technical evidence. P0/P1, credential, execution permission, scan blind-spot, and provider classification rules
cannot use this path.

The “Safe changes and recovery (Advanced)” area separates manual credential migration from automatic configuration hardening.
Terminal commands have an explicit copy action, while automatic remediation shows a per-file diff before changing anything.
Application requires the preview fingerprint to still
match, a native macOS confirmation, and a mandatory backup. AgentGuard rescans immediately after application. Restore stops
safely if another tool has changed a file since application.

Desktop diagnostics remain local and contain only a timestamp, allowlisted operation name, success/failure state, and fixed
error category. They exclude project paths, provider endpoints, task IDs, configuration, and raw error text, and are exported
only when the user chooses a destination.

```bash
npm ci
npm run desktop
npm run desktop:preview:capture

# Double-clickable local development launcher (depends on this checkout and node_modules)
npm run desktop:pack
npm run desktop:dist

# Official release commands require signing and notarization credentials.
npm run desktop:release
npm run desktop:release:verify
```

Official builds use `electron-builder.release.yml` with Hardened Runtime, entitlements, mandatory signing, and notarization.
The local preview is generated with `osacompile` and launches the trusted Electron development runtime from this checkout. It
does not contact Apple and cannot be distributed independently. macOS 26 terminates standalone Electron apps without a notary
ticket, so independently packaged apps use only the release configuration with Hardened Runtime, entitlements, Developer ID
signing, and notarization. `desktop:dist` therefore stops with guidance instead of producing a misleading local DMG.

## Command reference

The table describes `0.0.6-pilot.4`. Primary scan and mutation commands support `--json`; `report` uses `--format json`.
Machine output includes `schemaVersion: 1` and `command`.

| Command | Purpose |
|---|---|
| `agentguard` | Unified first run: discovery, scan, actual chain, action groups, top three tasks, and next command. |
| `agentguard doctor` | List discovered agents and configuration paths without reading credential values. |
| `agentguard scan` | Deep-scan all agents and cross-agent correlations; exit with code `2` for high or critical findings. |
| `agentguard provider scan` | Show provider, `base_url`, and proxy-chain findings only. |
| `agentguard map` | Build the multi-agent configuration map and expand two-hop proxy chains. |
| `agentguard report` | Produce an archival HTML or JSON report. |
| `agentguard baseline --profile balanced --dry-run` | Preview limited reversible baselines for OpenCode, Claude Code, Gemini CLI, and OpenClaw. |
| `agentguard backup` | Back up the current supported configuration under the project's `.agentguard/backups`. |
| `agentguard credential backup <task-id>` | Back up only the Claude settings involved in the current plaintext-credential task. |
| `agentguard credential restore <backup-id>` | Preview a Claude migration restore; writing requires the returned `--confirm <fingerprint>`. |
| `agentguard apply --profile balanced --backup` | Apply supported baseline changes with a mandatory backup. |
| `agentguard restore` | Restore the most recent backup, or use `--id <backup-id>`. |
| `agentguard trust add/list/remove` | Manage project-scoped trusted or internal provider endpoints with an append-only audit trail. |
| `agentguard ignore add/list/remove` | Manage eligible project + agent + rule ID ignores. |
| `agentguard risk accept/list/verify/revoke` | Preview acceptance conditions, accept explicitly, audit, verify, or revoke stable tasks. |

### Reports and CI

```bash
agentguard report
agentguard report --format json
agentguard report -f html -o -
```

HTML reports are self-contained, offline files with escaped dynamic content and no external dependencies. They lead with
action priority, next steps, verification, and disposition. Aggregated tasks preserve every associated rule's next step,
verification, and acceptance condition. Copyable commands are labeled as full fixes, mitigations, or supporting steps;
static HTML never executes a local command.

`scan` and `report` return exit code `2` when high or critical risks remain, including cross-agent correlations, so they can
act as CI gates. Exit code `0` means no high-or-higher unaccepted risk was found.

```yaml
- run: npm install -g @wangmarsen/agentguard@next
- run: agentguard scan
- run: agentguard report -f html -o agentguard-report.html
  if: always()
```

### Risk acceptance and verification

```bash
# Without --confirm, this validates and prints all grouped conditions but writes nothing.
agentguard risk accept task-xxxxxxxxxxxx --reason "Reviewed expected relay"

# Explicit acceptance.
agentguard risk accept task-xxxxxxxxxxxx --reason "Reviewed TLS and access control" --confirm
agentguard risk list --all
agentguard risk verify task-xxxxxxxxxxxx
agentguard risk revoke task-xxxxxxxxxxxx
```

Acceptance is scoped by an irreversible ID derived from the normalized current project and retains reason, optional expiry,
revocation, and static rule summaries. It does not delete evidence. P0 tasks require an explicit expiry. Task snapshots omit
evidence, paths, dynamic titles, and endpoints. Acceptance records default to `~/.agentguard/acceptances.json` with directory
mode `0700` and file mode `0600`.

### Baseline, backup, apply, and restore

The limited baseline covers:

- **OpenCode:** tighten dangerous Bash, sharing, automatic updates, and—under the safe profile—explicit edit/webfetch grants.
- **Claude Code:** remove `bypassPermissions`, unconstrained Bash/wildcard allow rules, and automatic project MCP enablement.
- **Gemini CLI:** change per-server MCP `trust=true` to `false`.
- **OpenClaw:** restrict non-loopback gateway exposure and public Tailscale modes.

Plaintext credential findings are not automatically rewritten by a normal baseline. AgentGuard may provide OS-specific secure
storage guidance, but it never claims completion without secure storage, a working configuration reference, old-credential
rotation, and a rescan. Codex TOML and CC Switch SQLite remain read-only because safe round-trip preservation is not available.
The `PROXY_MANAGED` value written into Claude Code, Codex, or Gemini CLI live configuration by CC Switch takeover is a public
authentication placeholder rather than a Provider key, so it does not trigger the corresponding plaintext-credential P0;
Claude also does not offer migration backup or Keychain guidance for it. AgentGuard labels an Agent as routed through CC Switch
only when both the global proxy service and that Agent's takeover route are enabled, then expands the local port and real
Provider. Real Provider credentials remain covered by separate CC Switch findings.

`apply` requires `--backup`. Backups are user-only, include hashes and original permissions, and receive Git-ignore protection.
Writes use same-directory atomic replacement and automatic rollback on failure. Restore verifies integrity, path boundaries,
and concurrent modifications before overwriting anything.

Claude plaintext-credential migration has dedicated CLI recovery commands:

```bash
agentguard credential backup <task-id>
agentguard credential restore <backup-id>
agentguard credential restore <backup-id> --confirm <fingerprint>
```

Backup rescans and requires a current `CLAUDE_PLAINTEXT_TOKEN` task, then copies only the affected `settings.json` and
`settings.local.json`. The first restore command is read-only and returns a fingerprint. The confirmed command writes only if
the backup, Claude path boundary, and current-file fingerprint still match. Restore reintroduces the old plaintext fields and
is only a fault-recovery step; the old credential still needs rotation and migration. Desktop uses the same core transaction
while retaining session-only authorization and native macOS confirmation.

## Privacy and security commitments

- **Read-only by default:** discovery and scanning do not modify agent configuration. Only explicit `apply`/`restore` or a
  fingerprint-confirmed `credential restore` changes supported files; acceptance, trust, and ignore commands write only their
  documented local/project audit state.
- **Local execution:** scans are performed on the machine and are not uploaded.
- **User-controlled diagnostics:** Desktop diagnostics use fixed fields, exclude sensitive context, and are never uploaded
  automatically.
- **Redacted output:** complete API keys, tokens, and private keys are excluded. Credential correlation uses SHA-256 fingerprint
  prefixes, MCP environment data reveals key names only, and `base_url` is displayed only as the endpoint identifier needed
  for remediation.
- **Explainable findings:** every risk includes evidence and guidance. Unknown endpoints are surfaced for review rather than
  blocked without context.

## Supported agents

| Agent | Depth | Coverage |
|---|---|---|
| CC Switch | Deep | Providers, base URLs, plaintext credentials, shared fingerprints, and built-in reverse-proxy chains. |
| Codex | Deep | Custom providers, remote/stdio MCP, plaintext credentials, trusted projects, and proxies. |
| Claude Code | Deep | Base URLs, plaintext tokens, bypass permissions, dangerous allow rules, hooks, and MCP. |
| OpenCode | Deep | Custom providers, plaintext credentials, Bash permissions, sharing, updates, and MCP. |
| Gemini CLI | Targeted deep scan | MCP trust, remote/stdio MCP, MCP environment key names, `.env` credentials, and unsandboxed shell. |
| OpenClaw | Targeted deep scan | Secrets, gateway exposure, Tailscale public modes, workspace conflicts, and unknown plugin sources. |
| Current project | Basic | Sensitive file names such as `.env`, private keys, cloud credentials, and kubeconfig; file contents are not read. |

Provider classification distinguishes official OpenAI, Anthropic, Google, and Azure services; supported Chinese official
providers; local/internal services; public bare IPs; and unknown relay endpoints.

### Provider trust

```bash
agentguard trust add https://ai.example.com/v1 --kind trusted --reason "Reviewed TLS and access control"
agentguard trust list
agentguard trust remove ai.example.com --kind trusted --reason "Service retired"
```

Trust affects unknown/relay classification only. It never suppresses plaintext HTTP, credential, or permission findings.
Reasons are appended to project configuration and may be committed, so they must not contain secrets.

### Project rule ignores

```bash
agentguard ignore add task-xxxxxxxxxxxx --rule OPENCODE_MCP_LOCAL --reason "Reviewed pinned project documentation MCP"
agentguard ignore list
agentguard ignore remove OPENCODE_MCP_LOCAL --agent opencode --reason "MCP removed"
```

`ignore add` rescans and validates the task ID, agent, rule ID, and disposition matrix. It stores no evidence, endpoint, path,
or task ID. Use risk acceptance for a specific temporary task and provider trust for a verified endpoint owner.

## Architecture

AgentGuard uses an adapter architecture. Each agent adapter separates discovery, privacy-preserving parsing/normalization,
and finding generation. A shared core handles cross-agent correlation, stable task identity, remediation, acceptance, triage,
provider trust, eligible rule ignores, baseline planning, transactional writes, reports, and output contracts. The desktop
service is the only business bridge between core and Electron; the sandboxed renderer receives only allowlisted typed IPC.
